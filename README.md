# FrDomianReview

Статический инструмент коллективной ревизии 657 файлов публичного каталога «Домиан Франчайзинг».

## Использование

Опубликованный интерфейс: <https://lesauteur.github.io/FrDomianReview/>.

Страница показывает всё дерево каталогов. Для каждого файла можно выбрать один статус: `KEEP`, `ARCHIVE`, `UPDATE`, `DUPLICATE`, `DELETE` или `UNSURE`. Повторный выбор того же статуса возвращает файл в состояние без статуса.

Перед работой выберите сотрудника в верхней панели. Доступны Егупов Алексей, Андрейченко Валерий и Марина Олеговна. Выбранное имя сохраняется только на устройстве и записывается как автор статуса или нового комментария.

Под файлом можно добавить комментарий; история не редактируется и не удаляется. Черновик привязан к точному `path` и хранится только локально. В центральном отчёте комментарии лежат в массиве `comments` с уникальными `id`, `author`, `text` и `created_at`. Старые записи без массива комментариев совместимы с новым интерфейсом.

Каждое изменение немедленно сохраняется в `localStorage`. При наличии несинхронизированных изменений страница отправляет их в `data/review-decisions.json` раз в 15 секунд, после 10 изменений или по кнопке «Сохранить сейчас».

## Доступ к GitHub

Для онлайн-сохранения проверяющий один раз вводит fine-grained personal access token. Токен должен иметь доступ только к репозиторию `LeSauteur/FrDomianReview` и единственное необходимое repository permission:

- `Contents: Read and write`.

Другие репозитории и permissions не нужны. Токен хранится только в `sessionStorage` текущего браузера, не включается в HTML, JavaScript, экспорт, сообщения об ошибках или Git-коммиты.

Чтение центрального отчёта выполняется через GitHub Contents API. Перед записью интерфейс получает актуальный SHA. При `HTTP 409` он перечитывает онлайн-версию и повторяет запись ровно один раз. Статус выбирается по более новому `reviewed_at`, комментарии независимо объединяются по уникальному `id` и сортируются по `created_at`.

## Локальный резерв

Без токена интерфейс продолжает работать с локальной копией. Кнопки «Экспорт JSON» и «Импорт JSON» позволяют создать резервную копию или восстановить решения вручную, включая историю комментариев.

## Сборка

HTML генерируется из уже существующего индекса без обращения к Яндекс.Диску:

```powershell
./scripts/build-review.ps1
```

## План будущего удаления

Dry-run план строится локально:

```powershell
./scripts/build-delete-plan.ps1
```

Скрипт читает `data/yandex-disk-index.json` и `data/review-decisions.json`, выбирает только решения `DELETE` и создаёт:

- `reports/delete-plan.json`;
- `reports/delete-plan.csv`.

Схема следующего, отдельного этапа:

```text
завершена ревизия
↓
review-decisions.json
↓
build-delete-plan.ps1
↓
ручная проверка delete-plan
↓
отдельный authenticated Yandex Disk cleanup script
↓
явное подтверждение
↓
удаление только файлов из delete-plan
```

**Статус DELETE сам по себе никогда не удаляет файл.** В этом репозитории нет OAuth Яндекс.Диска, delete API или cleanup-скрипта.
